# 012 — تدقيق اعتماديات الخادم (pip-audit)

**الحالة:** مقبول · **التاريخ:** 2026-10-26 · **مرتبط بـ:** ADR-002

## المنهج
`pip-audit --strict` يعمل في CI بعد تثبيت المتطلبات، ويسأل GitHub Advisory DB لكل باقة. محلياً
استُخدم `api.github.com/advisories?ecosystem=pip&affects=<package>` للتأكد من أول إصدار مُصاح.

## الأرضيات الناتجة (في `backend/requirements.txt`)
| باقة | السبب | الأرضية |
|---|---|---|
| `urllib3` | GHSA في الإصدارات <2.7.0 (تسريب `Proxy-Authorization`) | `>=2.7.0` |
| `requests` | CVE-2024-47081 | `>=2.32.5` |
| `starlette` | GHSA-422c-pjqp-cp3p وGHSA-p94p-q73i-4w9w | `>=0.47` |
| `python-multipart` | نفس السلسلة | `>=0.0.32` |
| `PyJWT` | `>=2.10` مطلوب لـ `algorithms` الصريحة + `jwt.decode` زمني | `>=2.12` |
| `aiohttp` | GHSA-mf9v-mfxr-j63j | `>=3.12.14` |
| `asyncpg` | لا ثغرة مفتوحة عند المراجعة؛ رُفعت لأحدث مستقر | `>=0.31` |

## باقات فُحصت ولم تُضف
- `setuptools`: ليست اعتمادية تشغيل في صورتنا، فلا أرضية لها هنا؛ تُراجَع إن احتاجها مسار البناء.
- `Pillow`: غير مستخدمة (التقارير CSV/نص، واللقطات يولّدها المتصفح في CI) فلا تُثبَّت.

## قرارات
- الأرضيات لا التجميد؛ الحلّ النهائي يحدث داخل صورة Docker وقت البناء.
- `pip-audit --strict -r requirements.txt` في وظيفة Backend بعد التثبيت؛ عند سقوطه نرفع الأرضية
  ونحدّث هذا الجدول في نفس الطلب، بلا تجاوز عبر `--ignore-vuln`.
