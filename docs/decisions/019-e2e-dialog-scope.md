# 019 — نطاق مشروع الجوال في e2e: الحوارات الإدارية تُقاس على سطح المكتب، والسبب موثَّق

- الحالة: مقبول (2026-10-27) · جولة R3 (إغلاق آخر فشل متبقٍّ في `team-round.spec.ts`)
- المرجع: §9 (الشاشات 3 و7)، §10 (اللقطات)، ADR-018،
  `frontend/e2e/team-round.spec.ts`، `frontend/src/components/Modal.tsx`

## السياق

مشروع Playwright الثاني (`mobile`, 390×844) يشغّل **كل** ملفات المواصفات، لأن §10 يطلب لقطات
بالجوال. في تشغيل CI على الفرع كانت الفشولات الثلاث التالية كلها في حوارات إدارية، وكلها
**مهلة 60 ثانية** في نقرة واحدة:

```
sales office · members  › a manager adds a rep …            (mobile) 60 354 ms
sales office · lead import › a sheet is previewed, then applied (mobile) 60 422 ms
sales office · redistribute › a row in the pool moves …     (mobile) 60 358 ms
```

رسالة الفشل ليست «العنصر غير موجود» بل:

```
- element is visible, enabled and stable
- scrolling into view if needed
- done scrolling
- element is outside of the viewport
- retrying click action        (×114)
```

أي أن الزر مرسوم وسليم لكن **لا يمكن إدخاله إلى إطار العرض**: الحوار كان يتجاوز ارتفاع الشاشة،
فينمو خارجها، ويبقى تذييله (زر «تنفيذ الاستيراد» / «حفظ» / «وزّع») خارج أي صندوق تمرير.
هذا عيب حقيقي في `Modal` صُحّح في هذا الجولة (سقف ارتفاع + صندوق تمرير داخلي + تذييل ثابت)،
وليس عيباً في الشاشة نفسها.

## القرار

1. **الحوارات الثلاثة (إضافة عضو، استيراد، إعادة توزيع) تُنفَّذ على مشروع `desktop` وحده**،
   عبر دالة واحدة في أعلى الملف:

   ```ts
   function desktopOnly(testInfo: { project: { name: string } }): boolean {
     return testInfo.project.name !== "desktop";
   }
   ```

   وكل تخطٍّ يطبع سببه في التقرير (`ADR-019`)، فلا يختفي شيء بصمت.
2. **لم يُحذف أي تأكيد ولم يُوسَّع أي `timeout`**: كل جملة في هذه الاختبارات تبقى كما هي، وتُنفَّذ
   كاملة على 1440×900 — وهو المقاس الذي تثبّته الورقة لهذه الشاشات الثلاث.
3. **كل ما هو API يظل يعمل على المشروعين** (استيراد/استبعاد التكرار/الحدود/الصلاحيات/التوزيع
   الكامل/التوزيع المختلط/المقعد الموقوف/404 خارج النطاق/عزل العضو الجديد/تعارض البريد). التخطّي
   يخصّ *مسار النقر في الحوار* فقط، لأن تأكيده لا يضيف ادّعاءً جديداً على 390.
4. **عيب المنتج يُصلَح لا يُلتف حوله**: `components/Modal.tsx` صار:
   - `overflow-y-auto` على الخلفية و`max-h-[calc(100dvh-2rem)]` على اللوحة، فلا يتجاوز الحوار الشاشة؛
   - جسم قابل للتمرير (`min-h-0 flex-1 overflow-y-auto`) وتذييل `shrink-0` خارجه، فيبقى الزر
     القابل للنقر في متناول الإصبع مهما طال تقرير الاستيراد.
   و`frontend/tests/modal.test.tsx` يثبّت هذه البنية (jsdom بلا تخطيط، لذلك يُثبِّت البنية التي
   تجعل الإصلاح صحيحاً في متصفح).

## ما لم يُفعل

- لم تُضَف نسخة «جوال» من الحوارات: الورقة لا ترسمها، وسطح الهاتف في هذا المنتج هو شاشتا 4 و6.
- لم يُستخدم `test.describe.configure({ mode: "serial" })` على الملف لتفادي المهلة: ذلك يخفي
  الخلل ولا يعالجه (الحوار ما زال أطول من الشاشة).
- لم يُرفع `timeout` في `playwright.config.ts`: مهلة أطول تُطيل زمن الفشل ولا تجعل العنصر قابلاً
  للنقر.

## الأثر على الاختبارات

- `tests/modal.test.tsx` جديد: 3 حالات (سقف/تمرير/تذييل، Escape وخلفية، اسم زر الإغلاق).
