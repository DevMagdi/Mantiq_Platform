# R8 — المخرجات الخام (raw)

كل رقم في `docs/qa/load/r8-load-2026-10-28.md` مقتبس من ملف هنا. لا يوجد رقم مكتوب باليد.

كل تشغيل Locust أنتج خمسة ملفات: `*_stats.csv` (الجدول الذي يُقرأ منه)، `*_stats_history.csv`
(ثانية بثانية — منه يُحسب الانزياح)، `*_failures.csv`، `*_exceptions.csv`، و`*.html`.
وكل `*.txt` هو سجل التشغيل نفسه (بما فيه سطر `Shutting down` ورمز الخروج).

| الملف | ما يثبته |
|---|---|
| `s1-smoke.*` | S1 — 10 مستخدمين × دقيقتان، خليط القراءة |
| `s2-10/25/50/75/100.*` | S2 — السلّم 10→100، دقيقتان لكل درجة |
| `pin25.*`, `pin50.*`, `s2-25-cpu.txt`, `pin50-cpu.txt` | إعادة S2 مع تثبيت النواة (`taskset`) — لإثبات أن السقف داخلي لا تنازع أجهزة |
| `after-s2-25.*`, `after-s2-50.*` | نفس درجتي السلّم بعد إصلاح `auth.login` (قبل/بعد) |
| `s4-realtime.json` / `.txt` | S4 — 40 بثًّا حيًّا × 300 ثانية + قراءات و`login` أثناءه |
| `s5-writes.*` | S5 — مسار الكتابة (`LOAD_MODE=write`) 25 مستخدمًا × 3 دقائق |
| `s6-endurance-401-run1.*` | المحاولة الأولى في S6 — **فاشلة لسبب في الاختبار**: الرموز تنتهي بعد 15 دقيقة والمستخدم لا يجدّدها (49.36% 401) |
| `s6-endurance-before.*` | S6 قبل إصلاح `auth.login` — 25 دقيقة، 25 مستخدمًا، مع تجديد الرمز |
| `s6-endurance-after.*` | S6 بعد الإصلاح — 20 دقيقة، نفس الحمل |
| `s7-cpu-sample.*` | عيّنة CPU لحظية للـAPI أثناء حمل 25 مستخدمًا (5 دقائق) |
| `login-rate-{before,after}.json` | `login_probe.py` على نظام خامل: 2/5/10 تسجيلًا في الثانية |
| `login-rate-under-load-{before,after}.json` | نفس المقياس **أثناء** حمل 25 مستخدمًا — هنا ظهرت الـ500 قبل الإصلاح |
| `s7-login-under-load-stats.csv` | حمل الـ25 مستخدمًا الذي جرى بالتوازي مع العيّنة أعلاه |
| `api-server-before-queuepool.txt` | مقتطف حرفي من سجل الخادم **قبل** الإصلاح عند 11:25:00–11:25:05: تسجيلات دخول بـ19–35 ثانية وأثر `QueuePool limit of size 10 overflow 20 reached` (السجل الكامل 37MB لم يُودَع؛ المقتطف هو الأسطر نفسها) |
| `api-server-after-queuepool-count.txt` | ناتج `grep -c QueuePool` على سجل الخادم **بعد** الإصلاح = **0** |
| `ci-s3-browser.json` | أرقام S3 من تشغيل CI `40690660084` (مقتطف من تعليق الـPR؛ الملف الكامل في artifact `r8-browser-load`) |
| `api-server-after-sample.txt` | آخر 2000 سطر من سجل ما بعد الإصلاح (بلا ANSI) — القراءات والكتابات أثناء S6/التحمّل |

الخلاصة القابلة للتحقق بلا لغة إنشائية: `python backend/scripts/load/summarize.py docs/qa/load/raw`
يطبع جدولًا لكل ملف `*_stats.csv` (وهو ما بُني عليه التقرير).
